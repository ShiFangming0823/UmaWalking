# UmaWalking 1.0.0：数量上限与实验性设置

控制面板标题为 **UmaWalking**。程序文件名和原配置文件名保留，现有快捷方式、数据目录、角色范围与地面设置可继续使用。

## 模型上限数量

在“角色与地面”→“当前角色”底部调整 **模型上限数量**，可选1～10，默认6。设置即时生效并保存；强制重启也保留最后选择。

- 自动入场和“指定角色上场”共用这个上限，正在进入、正在退出的角色都占用名额。
- 调大后可继续补位，手动排队的角色优先；后续角色按原入场间隔逐步增加。
- 调小后，超过目标数量的角色走向出口再消失。退场途中，屏幕总数可能暂时高于新设置，但不会继续添加角色。已经退场的对象不会被重复计为新一轮超额，不会把保留角色也清空。
- 优先保留手动指定的角色，其次保留更早入场者。如果手动角色本身超过新上限，同样会安排多余角色退场。
- 全随机与Exclude仍不重复同名；可用角色不足时只生成可用数量。
- Include有效角色数少于设定上限时，允许使用不同服装补足，同名服装仍不重复。例如上限10且Include只选一位，最多出现10套不同服装的该角色。有效名单达到上限时恢复同名唯一；空Include不随机生成角色。
- 暂停时可以修改上限，模型仍不移动、不新增；恢复后继续完成退场和补位。换装沿用原名额，不会额外生成第11只。

数量越高通常需要更多CPU、GPU和内存；可以结合15/30FPS与抗锯齿设置调整。

## 三维地面角色避让（实验性）

位于“设置与诊断”。新配置默认不勾选；已有手动选择会保留。开启后仅作用于三维地面，可随时关闭；二维直线与默认屏幕底边不启用该规划器。

## 验证范围

纯逻辑覆盖1～10所有上限、队列准入、候选数量不足、空Include、手动名额、十个唯一有效渲染层与上限缩小的计数。真实Unity程序验证1～10逐档达到目标、十个独立模型渲染、满员排队、10→3→1缩减、手动角色溢出、单角色十套衣服、换装过程中调限、暂停变更、Include/Exclude切换、不同地面、实验性避让、重启保留和十模型自然轮换。结果见验证记录。
