# UmaDesktop 3.1 及第三版资源占用评估

六角色版本明显重于第二版单角色程序。当前渲染进程约占 **0.84 GiB 驻留、1.35 GiB 私有提交内存**，还需控制面板和系统桌面合成开销；不能视为已经通过低配验收的轻量桌面程序。低配建议先用两角色低功耗模式。

## 3.1 修复后的复测

即时蒙皮刷新及描边修复后的六角色压力负载，渲染进程采样约 45 秒：平均总 CPU 4.23%、采样最大 6.69%，平均驻留 861 MiB、私有提交 1,363 MiB，进程 GPU 3D 平均 12.8%。控制面板和 DWM 不计入这组数值。与下方旧版测量的随机姿势和加载时刻不完全相同，不能据此宣称性能提升。原始数据为 UmaDesktop验证记录/v4/performance-six-render-fix.json，带当前程序集哈希。原低配建议继续适用。

下方保留第三版详细测量条件与历史数据，不能当作 3.1 每一项的重新测量。

## 条件与方法

2026-10-18，Windows 10 专业版 19045；i9-11980HK（8 核 16 线程）、RTX 3080 Laptop GPU、约 63.8 GiB 内存，主屏幕 3840×2160。没有运行游戏客户端参与渲染。使用最终 Windows x64 Mono 构建、逐像素透明窗口、4×MSAA／内部 FXAA；每角色输出窗口 768×768。

六角色测试用八名代表角色及加速轮换时序，采样约 51 秒、31 点，期间保持 5～6 只，包含换角、出入场及演出。它是压力负载，正式默认添加间隔为 20～35 秒，并非按相同时序。低功耗测试为正式全角色池与默认时序，最多两只、15 FPS、75% 内部渲染（约 576×576）、2×MSAA；启动约 8 秒后采样 65.5 秒、47 点，覆盖 1～2 只及轮换。

CPU 以进程累计 CPU 时间差除以墙钟时间和 16 个逻辑处理器，接近任务管理器的总 CPU 百分比。GPU 取进程 3D 引擎计数器。分别采样渲染进程和控制进程；系统 DWM、其他 GPU 引擎、冷启动最初数秒和瞬时峰值不在表内。

打开面板的压力测试合计平均约 **6.85% 总 CPU、949 MiB 驻留、1,453 MiB 私有提交**。低功耗两个进程合计平均约 **2.49%、698 MiB 驻留、882 MiB 私有提交**。两个进程采样窗口接近但不完全一致，合计为平均值之和，不是同步绝对峰值。

面板打开时仍有可观的 WinForms 布局／刷新开销，平时建议最小化或隐藏；这会保留托盘控制。最小化测试读数低于计时分辨率，不代表程序永久零成本。六角色渲染进程的 CPU 时间平均约为本机一个逻辑核的 71%，两角色低档约为 40%；线程较少或单核更慢的机器，总 CPU 百分比和掉帧风险都会增加。

驻留内存与私有提交不是同一概念，**不能相加**。Unity 运行时、完整资源索引、着色器和缓存有常驻开销。透明窗口需异步 GPU 读回并经 CPU／GDI 提交，每只都有独立缓冲；因此降低内部渲染分辨率和帧率并不能按比例降低全部成本。六只同时运行与第二版单只的旧测量不能直接类推。

GPU 百分比仅适用于本机 RTX 3080；集成显卡可能远高于此。专用显存和共享内存读数属于驱动估计，Microsoft 已记录部分 Windows 的进程 GPU 内存计数器误差，因此不作为最低显存要求。Microsoft 说明 (historical attachment)。DWM 的额外合成、功耗瓦数、温度、续航和是否唤醒独显均未测量。

## 低配判断

- 8 GB 及以上内存、较新的 D3D11 集成显卡：先使用“Launch-Low-Power.cmd”（两只／15 FPS），观察同时打开浏览器或游戏时的表现，再逐步增加角色。
- 4 GB 内存、旧双核／四线程或老旧集成显卡：额外约 0.7 GiB 驻留负担不可忽略；建议将 MaxActors 再降到 1。即使降低帧率，内存不足与换页仍可能造成卡顿，不能保证适合常驻。
- 默认六角色：建议留出约 1 GiB 以上驻留内存余量及更高提交预算；本轮未在实际低配机器验证，不将这些观察当作官方最低配置。

目前暂停会停止移动与动作，但仍维持窗口绘制；没有全屏游戏检测或遮挡自动休眠。长期不需要时直接退出更省资源。加载模型会同步读取和组装资源，仍可能出现短暂帧尖峰；提前切回移动主要解决专属动作尾部的等待，不是消除所有磁盘／组装停顿。

## 复现与证据

使用补丁中的 Measure-Desktop.ps1 分别测量两个进程；Test-Performance.ps1 可启动低档测试，Test-Fleet.ps1 复现加速六角色测试。原始逐点数据为 UmaDesktop验证记录/v3/performance-six-final-main.json、performance-six-final-controller.json、performance-lowpower-main.json 与 performance-lowpower-controller.json。

本次渲染程序集 SHA-256：`8E68185E28E85B6F2C515DB9C6AFB340C0F108728214CEDD0DAD2E143EA336CC`。控制程序测量时的 SHA-256：`E3F4C4E64D60F87124EDAFA0F7A8E922725A055C89002F058FF9CFB7F0F0A3CE`。测量后另修复了连续命令同时间戳的排序，并通过实际控制程序自检；持续布局／刷新路径没有变化，交付文件的最新哈希见 release-manifest.json。目录里另有早期的 performance-six-actor-stress.json，仅为开发阶段对照，不用于上表。

本轮最终六角色回归约 100 秒，不能证明数小时／数天运行没有增长，也没有完整覆盖 4,080 个服装组合。进一步优化可优先减少全窗口读回／GDI 拷贝面积、精简索引及着色器、降低面板刷新开销，并增加全屏或遮挡休眠；承诺最低配置前需要目标低配机器的长时间测试。

## 3.2 全屏遮挡后的待机占用

桌面完全被应用窗口盖住时不再渲染角色，动作、移动和出场计时均暂停，主循环降至 2 FPS。六角色本机短样本对比（各 8 秒）：CPU 总占用约 3.85% 降至 0.18%。暂停后仍保留模型内存以便恢复；这个结果不等于释放内存或显卡完全无负载。桌面重新露出后恢复正常帧率。详情与测试边界见“UmaDesktopDesktop-Occlusion-Pause.md”和验证记录 v5。
