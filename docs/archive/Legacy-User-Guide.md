## 操作

任务栏中有 UmaDesktop 控制面板图标，通知区域也有托盘图标。左键托盘打开面板，右键托盘直接显示专属动作、更换角色、随机换装、暂停和退出菜单。任务栏左键恢复面板后可以执行同样的操作。面板关闭按钮只隐藏面板，真正退出请点“退出程序”。若托盘图标被 Windows 收起，可在通知区域展开查看。

面板顶部先选择屏幕上的马娘，然后可以更换该角色、选择一套服装、随机换装或播放专属动作。更换角色会让原角色从边缘离开，再等补位间隔；更换衣服保留角色身份及位置，先淡出、重新加载、再淡入。随机换装排除当前衣服，仍按服装类别权重抽样；直接指定衣服则使用所选衣服。

**单击角色可见的身体区域并松开鼠标，会立即请求播放专属动作。** 按住并拖动则暂停该模型的动作，松开后接着播放。模型落脚点限制在地面内，也可以跨地面拖动；详情见《Dragging-and-Scale.md》。 透明区域的点击交给下面的应用。重复点击会重新抽取专属动作；如果正在双人互动，先解除双方互动。正在入场或离场时点击也会短暂打断移动。没有可用专属资源的角色会给出提示。程序暂停时动作也保持暂停。

| 快捷键 | 功能 |
|---|---|
| Ctrl+Alt+Q | 退出整个程序 |
| Ctrl+Alt+P | 暂停／继续 |
| Ctrl+Alt+N | 让最早入场的角色离场，随后补位 |

角色挂载在 Explorer 桌面层，只在桌面露出的区域显示；普通应用会遮住角色。只支持主屏幕。启动另一个模式前退出当前实例。

## 自定义地面

控制面板新增“地面”：选择“二维直线”或“三维四点地面”，点击“绘制 / 编辑地面”，在半透明桌面画布上绘制。二维点击两个端点；三维按远左、远右、近右、近左点击四点，再在边缘各点两次指定入口宽度与出口宽度。可添加最多三块地面，各角色出场等概率选择一块；保存后自动记住。编辑时暂停角色，Esc 取消。先显示桌面再打开面板，方便透过画布对齐壁纸。详见同目录《Custom-Grounds.md》。

## 角色范围与随机规则

面板提供全随机、Include、Exclude 三种模式。Include 只随机勾选的角色，Exclude 排除勾选的角色。支持名称／编号搜索、多选，以及全选或清空当前搜索结果。两份名单分别保留，点击“应用角色范围”后生效并保存。Include 一个都不选时，屏幕保持空白；Include 选择的有效角色数量少于设定上限时，允许同一角色使用不同服装逐步补足设定上限；同名角色的服装在场上不重复。选满上限数量的角色、全随机和 Exclude 则继续保持同名唯一。更改范围后，不符合条件的现有角色先从边缘退出。

先抽角色，再抽服装类别：胜负服 50%，校服与训练服合计 30%，其他 20%；类别内在该角色可用的衣服中等概率抽取。某类别缺失时，对剩余权重归一化。数据目录识别出 136 个可组装迷你角色、28 种共享服装，共 4,080 个角色／服装组合。这是资源及依赖存在性检查，全部组合尚未逐个完成视觉验收。

普通角色基础目标高度 380 像素，菱曙 570 像素，延续第二版的 2 倍／3 倍尺寸。实际可见高度随姿势变化。

步行与跑步以 3:1 抽取，持续 10～24 秒，再播放一次角色专属动作。整套开始／循环一轮／结束的总时长提前 **1 秒**切回移动，附加约 0.10 秒姿势混合；帧率影响触发精度。步态、专属及配套轨道在入场前预载，避免结束时临时读盘。通用衣服使用该角色默认个人服装的专属动作。

普通角色步行 65 像素／秒、跑步 260 像素／秒，菱曙按尺寸同比放大速度。程序采样脚踝接触地面的动画速度来调整播放速率，使跑步位移明显大于步行，并减少滑步；这仍是直线运动近似，没有地形 IK 或完全无滑步的保证。

## 多角色出入与双人互动

初始一只角色，之后每隔 20～35 秒增加一只，最多达到设定上限（默认六只，最高十只）；Include 少于设定上限的有效角色时允许不同服装的同名实例，其余情况下不重复同名；仍在退场的服装也会占用名额。新角色从屏幕左右边缘外进入，离场也必须走出边缘。满员后再等 20～35 秒，最早进入的角色向最近边缘退出。完全离开并释放后，额外等待 8～15 秒才添加新角色，随后重新计算满员周期。

角色与换装保留约 0.5 秒淡入淡出。出入场仍需实际越过边缘；资源加载可能让所有角色短暂掉帧，耗时取决于 CPU 与硬盘。

找到三组 `mini/set/...004_01_a/b` 配套动作并已接入。两只均为步行、方向相向且跨过相遇距离时，以 50% 概率触发一次同步互动；奔跑、出入场、正在互动的角色不参与。每次相遇只抽一次，并有冷却。该演出具有一方做手势、一方回应的配套姿势；“聊天／交流”是基于结构和实际姿态的用途判断，没有官方翻译标签、语音或文字。桌面控制站位，不使用原场景的相机和位置轨道。

## 地面、描边与抗锯齿

地面位于主屏幕物理底边上方 4 像素；使用实际鞋部包围盒及代表动作校准镜头，给鞋底留出安全边距。走动、抬脚和跳跃时鞋底会自然离开地面。底部任务栏或其他前景窗口仍可能遮住角色。

描边按每个角色的正交相机重新标定，OutlineWidth=0.45 表示约 0.45 个输出像素的参考宽度，不再是旧全局乘数；实际覆盖还受材质、顶点切线和抗锯齿影响。禁用额外粗描边，取消把背面向镜头拉近的描边深度偏移。贴图本身画出的线条不受此参数控制。正常模式使用 4×MSAA 处理轮廓，加透明安全的内部 FXAA 过滤衣服细节。身体贴图启用三线性过滤；面部图集保持原设置。透明合成改成逐像素 alpha，不再使用洋红色键。

数量上限在“角色与地面”底部直接调整；上限越高，渲染和内存开销通常越大。

`Launch-Low-Power.cmd` 临时使用 **最多两只、15 FPS、75% 渲染比例、2×MSAA**，桌面角色大小不变，不改写正常配置。重新正常启动即可恢复最多六只。低档清晰度和流畅度会降低；请先查看性能评估，多角色版本并非轻量常驻程序。

## 3.8 模型大小、强制重启与首位随机

控制面板“当前角色”区域新增“模型大小”滑块，范围 50%～150%，100% 为此前大小，对所有当前及后续角色生效并自动保存。普通角色约 190～570 像素高，菱曙约 285～855 像素高，继续保持相对 1.5 倍。调整时保持脚底地面位置，按尺寸同步调整位移速度、动画范围和避让范围；不重新加载角色。正在进行的双人互动会先结束，双方恢复移动再调整大小。暂停时也可调整显示大小，动画时间不前进。

控制面板底部和托盘右键菜单均有“强制重启”。该功能由独立辅助进程核对并结束本程序的旧主进程和旧控制面板，再启动一个新实例，即使 Unity 主线程卡住也可以执行。保留用户设置、滑块最新值以及原有启动参数（含低功耗模式）。重启会重新抽取角色；运行记录在 DesktopLogs/restart-status.json。

正常启动的首位角色从当前全随机／Include／Exclude 范围中抽取，不再固定为特别周。每次启动均重新随机，允许与上次相同。空 Include 名单仍不生成角色。旧 InitialCharacterId 字段不再控制正常首位出场。

滑块变大也会提高实际渲染和回读分辨率；150% 的像素量约为默认的 2.25 倍，50% 约为默认的四分之一。没有新增运行依赖。

## 3.7 步行表情权重

步行先按 Warai 组 80%、Sleep 组 20% 选择，再在组内等概率抽取。因此 WaraiA～E 各 16%，SleepA/B 各 10%。每次进入步行状态重抽，允许与上次相同。

## 3.6 Alt+Tab 与 FancyZones

Alt+Tab 切换界面和 FancyZones 拖动分区的提示层不再被当成普通的全屏应用。若操作前模型正在显示，操作期间保持显示和动画，不会因预览窗口、分区提示或中间布局触发主动隐藏。若操作前已因真实全屏而暂停，则保持暂停，避免把模型重新显示到应用上。

关闭切换界面或结束拖动后，重新判断实际桌面覆盖情况。露出桌面时立即恢复；真正完全遮挡持续约 0.75 秒后再自动暂停，避免切窗过渡闪烁。检测轮询与状态更新还会带来少量延迟。

角色继续挂载在桌面层。系统切换面板、分区蒙层和普通应用仍可自然遮住其下方部分；不会将模型改成置顶窗口，也不会显示在 Alt+Tab 的前景面板之上。PowerToys 设置窗口和实际排列好的应用仍参与正常遮挡检测。

20 项原生覆盖层兼容测试、17 项全屏／桌面回归，以及 17 项鼠标命中检查通过。原生兼容测试使用本程序创建的同类窗口夹具，未自动操作系统 Alt+Tab 或真实 FancyZones 拖动。详见“Window-Switching-and-FancyZones.md”。

## 3.5 点击与双人站位修复

桌面子窗口可能无法直接收到 Windows 的鼠标消息。现在由独立输入线程检查左键是否落在当前已显示模型的非透明像素上，再交给动作调度处理；不需要将窗口置顶。重叠时只触发最上面的一个模型，透明区域、前台应用挡住的区域、暂停或隐藏状态不响应。点击仍立即打断移动或双人互动，播放该角色专属动作，不受自动动作避让限制。

双人动作现在会按 A/B 角色、当前模型体型、实际动画范围安排双方站位，留出空隙；靠近边缘时整体向屏幕内部调整。其他移动角色会避让互动区域。若场地不足或会挤到其他角色，本次互动不开始。

三套双人动作分别以普通体型组合与菱曙组合检查，每组 61 个时刻，共 366 次双模型实际渲染测量；这些样本的最小可见间距约 104～164 像素。17 项原生输入检查覆盖安装、像素命中、上下层选择、透明穿透、前台遮挡、暂停、隐藏及线程卸载。该检查调用实际低级鼠标回调并使用真实窗口命中检测，不注入系统鼠标事件。截图接口仍超时，因此实际物理鼠标投递尚未自动验收，不能把这些检查等同于真实点击成功。

详见“Click-and-Pair-Spacing-Fix.md”。

## 3.4 动作与表情分配

| 新动作状态 | 表情规则 |
|---|---|
| 步行 | 80% 从 WaraiA～E 等概率抽取（各 16%）；20% 从 SleepA/B 等概率抽取（各 10%） |
| 专属动作 | WaraiA～WaraiE 五种等概率 |
| 跑步 | 90% 从 KiriA、KiriB、KiriC 等概率抽取；10% 从 GuruguruA、FightA 等概率抽取 |

新宇宙（1105）、金镇之光（1040）、气槽（1018）播放专属动作时保留游戏原生表情，不套随机笑脸；它们步行和跑步时照常随机。双人互动沿用专属动作的表情规则。

每次进入新动作重新抽取，可以与上一次相同。一次专属动作内部的开始、循环、结束片段共用同一表情；空间不足而继续步行／跑步等待时，也保留当前表情，直到真正切换状态。SleepA/B 是步行时可抽到的表情，不替换为睡觉身体动作。

表情同时设置左右眉、左右眼和嘴，使用此前 36 套图鉴的同一组参数。默认表情例外会先清除上一次随机表情的覆盖，再交由原生脸部轨道表现。没有额外运行依赖。详见“Motion-Expressions.md”。

## 3.3 随机速度与自动动作避让

每只新入场角色独立采样步行和跑步速度，默认分别是基准速度的 80%～120%。普通角色步行约 52～78 像素/秒、跑步约 208～312 像素/秒；菱曙仍按尺寸比例放大速度。角色在本次出场期间保持自己的速度，换装保留速度；下次重新入场再重新采样。播放倍率按脚底校准结果同步调整。

自动专属动作到点后，先检查该模型完整动作范围与其他角色是否有足够间隔。被挡住时保持当前步行或跑步，不站住等待，也不重新计时 10～24 秒；再实际移动约普通角色 76 像素后重试，直到空位足够。安全范围包括不同姿态和转身的保守外廓，双人动作范围另行计算。演出期间，靠近的屏幕内角色提前转向，入场或离场角色则在安全距离外暂缓前进，演出结束后继续。因此角色多、屏幕较小时，自动专属动作可能等待更久。

鼠标点击以及面板“播放专属动作”直接触发，不受自动动作避让条件限制。用户主动触发时允许模型临时重叠。沿用桌面层挂载和全屏自动暂停。

加载角色时预先测量并缓存动作范围，日常移动不做逐帧烘焙网格。详见“Random-Speeds-and-Clearance.md”。

## 3.2 桌面层与自动暂停

角色窗口现在是 Windows 桌面窗口的子窗口。普通应用会自然遮住角色，新角色入场也不会越过应用；仅在桌面露出的地方显示。旧的 AlwaysOnTop 配置与 Ctrl+Alt+T 置顶开关已停用。

当主屏幕的桌面工作区被不透明窗口完全盖住时，自动隐藏角色并暂停动作、移动、淡入淡出、入场、退场和补位计时，停止模型渲染与像素回读。全屏游戏、最大化应用、多个窗口拼满工作区都适用。任务栏不算桌面工作区。露出部分桌面后会自动恢复；3.6 对新的全覆盖增加约 0.75 秒稳定等待，不会追赶暂停期间错过的出场事件。

暂停后保留已加载模型的内存，主循环降到每秒 2 次以检查恢复和处理退出命令。手动暂停与自动暂停独立：如果手动暂停过，桌面露出后仍需手动继续。全屏下启动时会等待桌面露出再加载第一只角色。控制面板会显示“桌面被遮挡，已自动暂停”。

检测依据窗口可见矩形；最小化、系统隐藏或虚拟桌面上隐藏的窗口不计入。透明叠加窗口不会因矩形占满屏幕而误触发暂停；无法确定透明度的逐像素透明窗口按透明叠加处理。当前仍以主屏幕为范围。

已通过原生窗口层级与遮挡夹具测试、3,012 项覆盖面积检查及角色轮换回归。详细结果见“Desktop-Occlusion-Pause.md”。本轮没有依赖截图判断层级；实体桌面的观感仍可由用户继续核对。

## 3.1 渲染修复

修复了粗描边与手动渲染时的蒙皮缓存同步：每个 SkinnedMeshRenderer 在渲染时刷新矩阵、允许离屏更新并使用四骨骼权重，避免眼嘴刚性面片与头发／身体的蒙皮姿势错帧。四套代表模型完成 96 个姿势的正面／侧面对比；相同姿势下，描边外扩像素数量比旧参数减少约 92.9%。六角色约 100 秒回归也通过。详见同目录“Rendering-Fixes.md”。

## 验证范围与限制

早期版本曾完成约 100 秒加速回归：最多六只、9 次模型加载、4 次完整离场、87 次专属提前截断、3 次相遇抽签和 2 次双人演出；FIFO 与补位间隔通过。Include／Exclude／空名单、保留角色的换装和退出命令均通过端到端测试。独立逻辑及十万次概率抽样通过。六张当前引擎画面均有透明背景和半透明抗锯齿像素，鞋底没有碰到图像下边界。

**本轮真实鼠标点击与系统合成画面的自动验收未完成**：系统截图接口持续超时，随后点击工具报告缺少坐标几何。已验证原生点击回调分支、控制面板处理逻辑和本地命令链路，但这些不能替代真实鼠标输入。第二版的透明叠加曾由用户目视确认；第三版更换了合成方式，需要保留这个验证边界。原始记录见 UmaDesktop验证记录/v3。

耳朵、头发和尾巴有实际骨骼及弹簧参数；当前迷你角色没有完整启用 CySpring 物理解算，详见“模型与动作检查”。配套面部／耳朵资源会尝试加载，全部角色及所有哈希动画绑定尚未逐一验收。目前支持手绘二维直线和最多三块四点地面，暂不支持多屏、接触阴影或 Wallpaper Engine 发布。桌面完全遮挡时会自动暂停。
