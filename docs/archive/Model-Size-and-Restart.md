# UmaDesktop 3.8 · 模型大小、强制重启与首位随机

控制面板“当前角色”区的全局大小滑块支持 50%～150%。100% 为此前默认大小。设置自动保存，新角色沿用；菱曙保留相对放大比例。调整不重载角色，保持脚底地面位置、服装和随机速度系数，同步更新实际位移速度与安全间距。双人互动会在缩放前解除。

显示窗口和渲染纹理按尺寸一起调整，避免只放大模型导致画面边缘裁切。暂停时可更新大小，动作时间保持不动。尺寸越大，像素量和资源占用越高，150% 的像素量为默认的约 2.25 倍。

“强制重启”入口位于控制面板底部及通知区域的托盘右键菜单。辅助进程独立于 Unity 主循环，先验证进程路径与启动时间，再结束旧主程序和旧控制面板，等待它们退出后启动一个新实例。保存的设置、滑块最新值及启动参数会保留。使用命名互斥锁防止重复操作并发重启，状态记录为 DesktopLogs/restart-status.json。

正常启动的首位角色现在使用与后续角色相同的随机池，遵守 Include／Exclude。不会再优先选择旧配置中的 InitialCharacterId。允许连续两次启动抽到同一位角色。显式开发测试模式仍保留固定角色夹具，便于回归；日常启动脚本不包含测试参数。

无新增运行依赖。开发集成测试为 Tests/verify_size_restart.py（需要现有开发环境中的 Python、Pillow 和 psutil），验证记录位于 UmaDesktop验证记录/v11。

## 本轮验证

47 项端到端检查通过：两个模型从 50% 切到 150% 再回到 100%，实际窗口及渲染图大小正确；同一姿势的可见高度约为 3 倍关系，地面锚点与随机速度系数保留；菱曙在 125% 下高度为约 712.5 像素。尺寸可保存，暂停时调整不推进动作时间。

实际阻塞 Unity 主线程后，辅助程序成功结束旧进程并恢复运行，保留 125% 大小和原有启动参数。另完成两次正常重启，确认旧控制面板也结束，新实例正常运行。三次正常首位抽取为 1064、1006、1006，验证取消固定首位，同时也展示了跨次启动允许重复。

控制面板 16 项处理逻辑检查、原生像素命中与缩放后点击 20 项检查，以及动作、筛选、覆盖、速度和表情逻辑回归通过。控件处理逻辑测试不等同于真实鼠标拖动及系统截图验收；模型尺寸图由程序实际渲染输出。

六角色加速回归约 86 秒通过：9 次加载、3 次完整离场、19 次提前结束专属动作，FIFO 及补位间隔正常。本轮普通回归未实际开始双人互动；双人动画已有此前的专项记录，尺寸更新时解除双人会话的处理也保留在实现中。
